# Docker Image Signing & Supply Chain Security

Consistium uses **Cosign keyless signing** and **SLSA provenance attestations** to ensure that every Docker image deployed was built by the official CI/CD pipeline, from a known commit, and has not been tampered with.

## How It Works

### Cosign Keyless Signing

Traditional image signing requires managing private keys. Consistium uses **keyless signing**, which eliminates key management entirely:

1. **GitHub Actions OIDC**: The CI pipeline requests an identity token from GitHub's OIDC provider
2. **Fulcio (Certificate Authority)**: Cosign exchanges the OIDC token for a short-lived signing certificate
3. **Signing**: The image is signed with the ephemeral certificate
4. **Rekor (Transparency Log)**: The signature is recorded in Sigstore's public transparency log for auditability

The result: a cryptographic proof that the image was built by the `Kalpanapramodya97/consistium` GitHub Actions pipeline, from a specific commit.

### SLSA Provenance

The Docker BuildKit `provenance: mode=max` flag generates a [SLSA provenance](https://slsa.dev) attestation that records:

- **Source repository** and commit SHA
- **Builder** identity (GitHub Actions)
- **Build configuration** (Dockerfile, build args)
- **Materials** (base images, dependencies)

This provides **SLSA Level 1** compliance — proof of where and how the image was built.

### SBOM Attestation

The CycloneDX SBOM (already generated by Syft) is attached to the image as an [in-toto attestation](https://in-toto.io/) using `cosign attest`. This means anyone pulling the image can also inspect its full dependency list.

## Pipeline Integration

### Signing (in `docker-build-scan-push` job)

```yaml
# 1. Install Cosign
- uses: sigstore/cosign-installer@v3

# 2. Push with provenance
- uses: docker/build-push-action@v5
  with:
    provenance: mode=max
    sbom: true

# 3. Sign the image
- run: cosign sign --yes ${tag}@${digest}

# 4. Attach SBOM attestation
- run: cosign attest --yes --predicate sbom.json --type cyclonedx ${image}@${digest}

# 5. Verify (smoke test)
- run: cosign verify --certificate-identity-regexp="..." --certificate-oidc-issuer="..." ${image}@${digest}
```

### Verification Gate (in `semantic-versioning` job)

Before creating a GitHub Release, the pipeline verifies the image signature. If verification fails, the release is blocked:

```yaml
- run: |
    cosign verify \
      --certificate-identity-regexp="https://github.com/Kalpanapramodya97/consistium/" \
      --certificate-oidc-issuer="https://token.actions.githubusercontent.com" \
      ghcr.io/kalpanapramodya97/consistium/habit-tracker:latest
```

## Local Verification

### Prerequisites

Install Cosign locally:

```bash
# macOS
brew install cosign

# Linux
go install github.com/sigstore/cosign/v2/cmd/cosign@latest

# Windows (scoop)
scoop install cosign
```

### Verify an Image Signature

```bash
# Using Make
make verify-image

# Or with a specific image
make verify-image IMAGE=ghcr.io/kalpanapramodya97/consistium/habit-tracker:sha-abc1234

# Or directly
cosign verify \
  --certificate-identity-regexp="https://github.com/Kalpanapramodya97/consistium/" \
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com" \
  ghcr.io/kalpanapramodya97/consistium/habit-tracker:latest
```

### Inspect the SBOM Attestation

```bash
# Using Make
make inspect-sbom

# Or directly
cosign verify-attestation \
  --type cyclonedx \
  --certificate-identity-regexp="https://github.com/Kalpanapramodya97/consistium/" \
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com" \
  ghcr.io/kalpanapramodya97/consistium/habit-tracker:latest \
  | jq -r '.payload' | base64 -d | jq '.predicate'
```

### Inspect SLSA Provenance

```bash
cosign verify-attestation \
  --type slsaprovenance \
  --certificate-identity-regexp="https://github.com/Kalpanapramodya97/consistium/" \
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com" \
  ghcr.io/kalpanapramodya97/consistium/habit-tracker:latest
```

## Helm Digest Pinning

For production deployments, you can pin images by digest instead of mutable tags:

```yaml
# helm/environments/prod.yaml
image:
  digest: "sha256:abc123..."   # Immutable — guarantees the exact signed image
```

When `image.digest` is set, the tag is ignored and Kubernetes pulls by `repo@sha256:...`. This ensures the exact image that was signed and scanned is the one deployed — no tag mutation attacks possible.

## Security Properties

| Property | How It's Achieved |
|----------|-------------------|
| **Authenticity** | Cosign signature proves the image came from the official pipeline |
| **Integrity** | Digest pinning ensures the image hasn't been modified after signing |
| **Provenance** | SLSA attestation records source repo, commit, and builder identity |
| **Transparency** | All signatures are recorded in Sigstore's public Rekor log |
| **Non-repudiation** | The OIDC identity (GitHub Actions workflow) is embedded in the certificate |
| **Dependency Visibility** | CycloneDX SBOM attestation lists every component in the image |

## No Infrastructure Required

This entire signing flow runs using:

- **GitHub Actions OIDC** — built-in, no configuration needed
- **Sigstore Fulcio** — free public CA, no key management
- **Sigstore Rekor** — free public transparency log
- **Cosign** — open-source CLI tool

No KMS, no Vault, no key servers, no additional secrets.
